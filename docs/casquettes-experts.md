# HashCode Global Impact — Casquettes & Experts

## Purpose
Ce référentiel définit les rôles nécessaires pour transformer les 15 projets Global Impact en produits/prototypes validables. Une casquette décrit une responsabilité, pas un titre hiérarchique.

## Casquettes transversales

| Casquette | Mission principale | Livrables typiques |
|---|---|---|
| Product Lead | Transformer problème en produit testable | problem statement, MVP, roadmap |
| Domain Expert | Garantir la pertinence métier | règles métier, contraintes, validation |
| Field Researcher | Vérifier le terrain | entretiens, observations, synthèse |
| UX/UI Designer | Concevoir des parcours utilisables | flows, wireframes, UI |
| Software Architect | Structurer le système | architecture, ADR, diagrammes |
| Frontend Engineer | Construire l'expérience | interfaces, états, tests |
| Backend Engineer | Construire services et logique | API, services, données |
| Data Engineer | Fiabiliser les données | pipelines, schemas, quality checks |
| AI/ML Engineer | Construire et évaluer les modèles | datasets, baselines, evals |
| Cybersecurity Engineer | Réduire les risques techniques | threat model, controls, tests |
| QA Engineer | Vérifier les comportements | test plan, regression, E2E |
| DevOps/MLOps | Rendre le système déployable | CI/CD, observabilité, releases |
| Privacy/Safety | Encadrer données et risques | privacy review, safety cases |
| Impact Analyst | Mesurer les résultats réels | baseline, KPI, evidence |
| Documentation/Community | Rendre le projet transmissible | docs, onboarding, changelog |

## Niveaux de contribution

### Contributor
Peut prendre une mission bien définie et produire un livrable vérifiable avec revue.

### Active Contributor
Réalise régulièrement des missions, documente son travail et aide à débloquer le projet.

### Core Contributor
Maîtrise un domaine du projet, participe aux décisions techniques/métier et effectue des reviews.

### Lead
Porte une responsabilité de domaine ou de projet, définit les priorités et coordonne les contributeurs.

La progression est fondée sur les preuves de contribution, pas uniquement sur le diplôme ou le CV.

## Règle de recrutement

Ne pas recruter d'abord des personnes pour remplir des postes. Publier une mission concrète avec contexte, résultat attendu, effort estimé et critères d'acceptation. Le contributor choisit une mission adaptée à sa casquette.

`Casquette → Mission → Issue → Contribution → Review → Preuve → Niveau`

## Règle de sécurité

Les projets sensibles (santé, sécurité, données personnelles, fraude) nécessitent une revue spécialisée avant pilote. Les projets médicaux restent des outils d'aide à la décision sous supervision humaine et ne doivent pas être présentés comme des systèmes autonomes de diagnostic.
